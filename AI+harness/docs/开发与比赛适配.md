# 开发与比赛适配

## 当前运行路径

`run.py → harness_core.__main__ → runner.run_workflow → gas_runner.run_gas_mlp → gas_workflow.run_trainer_batches`。

只运行滑动窗口训练师 trainer_window_v4。rules 使用相同的批次流程和验证门槛，供离线调试和模型请求失败时兜底。旧搜索、固定配方和静态模型对照入口已移除。

B 轴承剩余寿命回放通过 `run --dataset bearing_rul` 进入，使用独立的回归数据适配、窗口提案和选模流程。与 A 共用特征漂移诊断、预算、运行锁、实验账本和跟踪。数据边界、命令和门槛见项目 README 的 B 轴承剩余寿命回放一节。

## 数据与模型

官方初始 MLP 已使用 batch1 训练，回放从 batch2 开始。每批按约 60%、20%、20% 分层划分为训练、验证和留出测试。漂移参考用最近 3 批训练集，续训用大模型选择的 1–8 批窗口，历史门槛用最近 6 批验证集。窗口 1 为仅本批。

优先目标取最近 4 批最终验证 Macro-F1 均值，首批使用 min_gain 增益门槛。候选须优于批初模型，并满足各历史组下降不超过 max_history_drop，默认 20 个百分点。候选从同一个批初模型训练，按当前验证分选模。选定后才读取留出测试成绩。

batch2 完整数据此前用于公开验证，报告将其标为开发留出。大模型接收本批验证指标、漂移摘要、最近决策和候选反馈。历史退化门槛由程序在最近 6 批验证集上检查。

模型特征顺序和类别由检查点提供。gas_import 支持 CSV、JSONL、DAT 输入检查与转换，映射说明见同目录的气体输入转DAT.md。

## 指标口径

保留当前方案的评分实现。gas_metrics 使用检查点声明的全部类别计算诊断与早停 Macro-F1，缺类记零。gas_data 沿用官方 Baseline 的 resource_monitor 进行选模和报告，类别范围为真值或预测中出现的类别。缺类批次会产生差异，比较结果时应注明口径；统一口径需另行重跑验证。

## 账本、恢复与日志

SQLite 账本按固定实验 ID 记录请求预留、训练预留、候选结果和批末选择。恢复时复用已完成记录。请求在中断前已发出但未收到响应时，仍计入请求预算。未完成且无有效训练产物的尝试记为中断，继续使用原模型。

保存的 trainer_window_v4 配置可恢复，旧配置中仅用于早期搜索的字段会被忽略。v3 及更早结果可查看历史 summary。

SwanLab 记录本批更新前后指标、训练参数、三个窗口、门槛、失败、API、Token 和最终汇总。online 初始化失败时可转本地记录，验收云端时须检查实际可见性。

BatchMeter 统计本地决策耗时、CPU 时间和进程树 RSS。远端模型推理资源不包含在本地测量中。中断后的片段测量标为不完整。

## 服务与平台

默认通过 PyTRiO 调用千问，可在开发时选择 DeepSeek。凭证优先读环境变量，其次读根目录 local_secrets.py。API 重试和格式修正计入请求预算，首轮失败用规则兜底，已有候选后的反馈失败结束搜索。兜底根据动态验证目标判断稳定性，样本不足时返回 NO_UPDATE，保留现用模型。

本仓库的入口运行本地回放。正式接口说明保留在 contest-harness-sdk-1.0.2/HARNESS_SDK.md，正式接入须核对批次与标签时序、模型目录、提交格式和运行资源。Dockerfile 用于本地打包验证。
